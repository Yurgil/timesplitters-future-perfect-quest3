# M3. Виртуальный экран и Quest Touch

APK `build/android/timesplitters-xr-debug.apk` использует пакет `org.tsfp.quest` и каталог сохранений M2. Запуск из библиотеки открывает виртуальный экран OpenXR. Оконный режим остаётся доступен через `adb shell am start -W -n org.tsfp.quest/.MainActivity` для сравнения.

Из корня проекта после подготовки M2 и сборки диагностического APK по M0:

```sh
android/build.sh
adb install -r build/android/timesplitters-xr-debug.apk
adb shell am start -W -n org.tsfp.quest/.XrActivity
```

В обоих режимах используется тот же Vulkan-рендерер. В OpenXR он копирует готовый кадр в swapchain композитора на GPU. Финальный проход использует размер XR-буфера 640×480, независимо от размера Android-окна. Виртуальный экран размещается перед пользователем при первом видимом кадре и заново центрируется при возвращении XR-фокуса. Прототип отправляет OpenXR-кадр после каждого игрового кадра. Цикл композитора с независимой частотой ещё предстоит проверить. [Спецификация OpenXR](https://registry.khronos.org/OpenXR/specs/1.1-khr/html/xrspec.html)

Оба Touch передают ввод первому Xbox-игроку через XR Actions. При потере фокуса кнопки и оси сбрасываются.

| Touch | Ввод Xbox |
| --- | --- |
| Левый Menu (☰) | Start, пауза |
| A, B, X, Y | Одноимённые кнопки |
| Левый и правый стики | Движение и камера |
| Нажатия на стики | L3 и R3 |
| Указательные триггеры | LT и RT |
| Каждая боковая кнопка Grip по отдельности | Плечевая кнопка, сопоставленная чёрной или белой кнопке Xbox |
| Обе кнопки Grip + левый стик | D-pad, в том числе смена оружия |

Проверочный маршрут проходит через `Story → 2401 — Time to Split → Normal`. После вступления проверяются движение, поворот камеры, выстрел правым триггером и пауза через левый Menu.

На Quest 3 APK установлен поверх M2 с сохранением данных. При запуске в надетом шлеме OpenXR активировал профиль Touch для обеих рук, игровой порт 1 получил физическое нажатие A. Для диагностики обрезки запуск с `--ez capture_frames true` также записывает `cache/frame-xr.bmp`. Этот снимок читается из финального кадра перед копированием в OpenXR swapchain.

## Базовый замер производительности

Пользователь подтвердил, что версия 0.3.1 показывает весь экран и запускает первый уровень кампании. В последних 15 односекундных записях VrApi процесса игры частота дисплея составляла 72 Гц, частота кадров приложения 11–12 FPS, GPU-время приложения 4,16–5,51 мс, повторов кадров 61–63 в секунду. Сцена и XR-буфер работали в 640×480. Точную долю игрового кода, подготовки Vulkan-команд и ожиданий следует измерить отдельно. Журналы сохранены локально в `logs/m3-quest-vrapi-baseline.log` и `logs/m3-quest-performance-baseline.log`. [Счётчики VrApi](https://developers.meta.com/vr/documentation/unity/os-missed-frames/)

```sh
TSFP_OPTIMIZE_GUEST=1 android/build.sh
```

Этот профиль включает `-O2 -fno-vectorize -fno-slp-vectorize` для сгенерированного ARM64-кода. Он пишет APK в `build/android-optimized/` с тем же ключом подписи. Обычная сборка остаётся в `build/android/`. Оптимизированный APK весит около 180 МБ. В ручном прогоне на Quest зафиксированы отрезки с 31–42 FPS и последние 20 секунд с 49–51 FPS при 72 Гц дисплея. Это сравнение ручных прогонов, без фиксированного маршрута. Журналы находятся в `logs/m3-quest-o2-vrapi.log` и `logs/m3-quest-o2-manual.log`.

Сравнить обе сборки на одном участке первой миссии при 640×480 и выключенном захвате кадров. Записать медиану и p95 времени кадра, GPU-время и число повторов. После этого отдельно проверить повышение разрешения финального XR-кадра и сцены до 960×720. Частоту XR и частоту обновления игровой сцены учитывать раздельно. Для 72 новых кадров игры в секунду проверить адаптацию таймингов из PC-порта, где оригинальный режим ориентирован на 60 FPS. [Тайминги PC-порта](https://github.com/TheDoffman/timesplitters-future-perfect-pc/blob/be641d9db1f12aa757213388738a24829d5fc083/docs/analysis/native-high-refresh.md)

В 0.3.3 Vulkan переиспользует неизменившиеся push-привязки ресурсов в пределах записи одного командного буфера и пропускает сброс кеша для когерентных буферов вершин и индексов. В оконной проверке меню на Quest за 900 кадров переиспользовано 396 763 из 489 378 привязок. В ручном прогоне первой миссии в OpenXR медиана составила 31 FPS, минимум односекундного замера 18 FPS при 90 Гц. Маршрут отличался от прогона 0.3.2, поэтому прирост FPS по этим данным не оценивался. Счётчик `[VK-PUSH]` включается при запуске с `--ez benchmark true`. [Правила совместимости привязок Vulkan](https://docs.vulkan.org/spec/latest/chapters/descriptorsets.html)

В ручном прогоне 0.3.3 с отмеченным фризом при первом попадании во врага зарегистрирована серия из 134 повторённых кадров при 90 Гц. Профиль CPU вокруг просадки показал высокую долю разбора текста в libc. Версия 0.3.4 заменяет `sscanf` в Android-проверках `/proc/self/maps` на специализированный разбор адресов и прав. В тесте ARM64 результаты совпали на 93 отображениях, а чистый разбор ускорился с 2,07 до 0,26 мс на 100 проходов по этим строкам. Проверки защиты страниц и владения памятью прошли на Quest. Обычный запуск также отключает подробную трассировку функций Xbox. Повторный замер первого попадания в игре остаётся открытым.
